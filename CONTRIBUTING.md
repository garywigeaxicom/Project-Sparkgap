# Contributing to Project Sparkgap

Thank you for helping improve this public AI design reference. Contributions should make the project clearer, safer, more technically rigorous, or more adaptable.

## Before You Start

- Read [README.md](README.md) and [DESIGN.md](DESIGN.md).
- Check existing issues, pull requests, and architecture decision records in `adr/`.
- Keep examples clearly separated from normative requirements.
- Do not include credentials, private data, undisclosed vulnerabilities, or proprietary material.

## Proposing Changes

For a substantial architecture change, open an issue or draft pull request describing:

- the problem or opportunity
- the proposed change
- alternatives considered
- effects on safety, privacy, cost, accessibility, and portability
- evidence, benchmarks, or references supporting the proposal

Use an ADR for a decision that changes a durable architectural direction. Documentation corrections and clarifications do not require an ADR.

## Review Expectations

Reviewers should consider technical accuracy, public readability, reproducibility, security, privacy, inclusion, operational feasibility, and vendor portability. A proposal may be accepted with follow-up work when the design direction is sound but implementation detail is intentionally deferred.

## Style

- Use clear Markdown headings and short paragraphs.
- Prefer precise, vendor-neutral language where possible.
- Define acronyms on first use.
- Link to authoritative references.
- Update the relevant changelog entry for material changes.
